# store

Written `plakarkorp.plakar.store` in a task.

Manage Plakar stores.

Creates, updates and deletes stores — where Plakar keeps backup data — in the
Plakar management API, initializing the underlying storage on creation.

Stores are matched by name within the organization; the name is the playbook's
key, so it must be unique among stores.

Only the options the playbook sets are managed on update; anything else keeps
its current server-side value.

## Examples

```yaml
- name: S3 store
  plakarkorp.plakar.store:
    name: Offsite S3
    protocol: s3
    integration: s3
    resource: Ample Sky
    environment: production
    compression: ZSTD
    fields:
      passphrase: "{{ vault_repo_passphrase }}"
      access_key: "{{ vault_s3_access_key }}"
      secret_access_key: "{{ vault_s3_secret_key }}"
      root: /backups
```

## Options

| Option            | Type        | Required | Default     | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------- | ----------- | -------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `api_key`         | str         | No       |             | API key of a service account, as minted by the Plakar API (`pcp_ak_...`). API keys authenticate without a second factor and are bound to one organization. The service account must hold a role in the organization (the `operator` role suffices for running backups and restores); without a grant the API answers with empty lists rather than errors. Falls back to the `PLAKAR_API_KEY` environment variable.                                                                                                                                                                                                                                                                                 |
| `api_url`         | str         | No       |             | Base URL of the Plakar management API, for example `https://plakar.example.com`. Falls back to the `PLAKAR_API_URL` environment variable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `compression`     | str         | No       |             | Compression for the store at initialization. Unset keeps the engine's own default. One of `GZIP`, `LZ4`, `ZSTD`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `data_classes`    | list of str | No       |             | Refused when set. The Control Plane only accepts data classes on a source connector.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `endpoints`       | list of str | No       |             | Endpoint names the store reaches its resource through.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `environment`     | str         | No       |             | Environment label, for example `production`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `fields`          | dict        | No       |             | Integration-specific configuration, as a mapping of field name to value. To take a value from a secret provider instead, give a mapping with `value`, the path of the secret in the provider, and `provider`, the name of the secret provider as `plakarkorp.plakar.secret_provider` declares it. `provider_id` takes its id instead of its name. On update, only the fields named here are compared and replaced; other existing fields are preserved. Must carry a non-empty `passphrase` when the store is initialized here, since it encrypts the store at rest. A field backed by a secret provider counts as set, because the provider supplies the value.                                   |
| `initialize`      | bool        | No       | `true`      | Whether to initialize the underlying storage right after creating the store. Initialization only happens on creation, never on update. When the storage fails to initialize, the task fails and the store it had just created is removed, so that the next run starts over instead of finding a store that was never initialized. Set it to false when the storage is already initialized elsewhere, which also lifts the passphrase requirement.                                                                                                                                                                                                                                                  |
| `integration`     | str         | No       |             | Name of the installed integration backing the store. Required when creating; immutable afterwards. Naming another one for an existing store fails the task.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `name`            | str         | Yes      |             | Name of the store.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `organization_id` | str         | No       |             | UUID of the organization to operate in, when different from the one the API key is bound to. The badge is re-scoped once per organization and cached for the duration of the task.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `protocol`        | str         | No       |             | Protocol spoken to the resource, for example `s3` or `sftp`. Defaults to the integration name, which matches for the standard integrations; set it only when they differ.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `resource`        | str         | No       |             | URN or name of the inventory resource the store attaches to. Required when creating; immutable afterwards. A URN and a name for the same resource are the same resource, and naming another one for an existing store fails the task. A store whose resource was deleted since is left without one, and the Control Plane then refuses any change to it but a new resource, which it takes in place.                                                                                                                                                                                                                                                                                               |
| `state`           | str         | No       | `present`   | Whether the store should exist. `absent` removes the store from Plakar; the data in the underlying storage is not touched. One of `present`, `absent`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `temperature`     | str         | No       |             | Storage temperature.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `timeout`         | int         | No       | `30`        | Timeout in seconds for each individual API request (not for job completion; the action modules have `wait_timeout` for that).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `update_secrets`  | str         | No       | `on_create` | When to send a value the API does not show. Since v0.19 the Plakar Control Plane leaves the value of a sensitive field out of what it returns, so the module cannot tell whether the one in the playbook differs from the one stored. `on_create` sends such a value at creation only. Later runs leave the stored one alone and report no change for it, also when another option of the same task is updated. `always` sends it on every run, which then reports a change each time. Use it for the run that rotates a credential. A value that references a secret provider is always shown, and so always compared, as is every value on an older Control Plane. One of `on_create`, `always`. |
| `validate_certs`  | bool        | No       | `true`      | Whether to validate TLS certificates when talking to the API.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

## Returns

| Key         | Type        | Returned                             | Description                                                                                                    |
| ----------- | ----------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `connector` | dict        | when the store exists or was created | The store acted on (a summary; field values are not echoed). Carries `initialized` when the module created it. |
| `diff_keys` | list of str | on update                            | The option names whose values differed and drove the update.                                                   |
