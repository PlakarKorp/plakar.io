## Security

- The repository database file is now created with mode `0600`, and the `-wal`
  and `-shm` files inherit it. This applies only when the repository is created.
  An existing database keeps its permissions.
  ([#182](https://github.com/PlakarKorp/integrations/pull/182))

## Fixes

- A failure to set `journal_mode=WAL` or `busy_timeout` is now returned as an
  error, and the connection is closed. Before, the connection was reported as
  successful while left unconfigured, and a lost `busy_timeout` made a contended
  database fail at once with `SQLITE_BUSY`.
- Writing a packfile or state that already exists now fails. Before, the
  constraint error was ignored and the write looked successful.
  ([#209](https://github.com/PlakarKorp/integrations/pull/209))
- Renewing a lock now updates its stored data. Before, the renewal hit the
  constraint and was ignored, so the old data stayed.
  ([#209](https://github.com/PlakarKorp/integrations/pull/209))
- The SQLite backend was registered twice, once without flags and once with the
  local-file flags. Only the local-file registration remains.
