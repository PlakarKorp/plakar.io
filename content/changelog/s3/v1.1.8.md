## New

- `access_key` and `secret_access_key` are now optional. When they are omitted,
  the connector uses the credentials of the environment it runs in: an EC2
  instance profile, an ECS task role, or EKS IAM Roles for Service Accounts and
  Pod Identity.

## Improvements

- Store creation is refused on a bucket with Object Lock enabled when the
  location still holds versions or delete markers of a previous store's
  configuration, since recovery would be ambiguous between the two stores. Use a
  new bucket or a different prefix instead.
- With path-style addressing, `root` is now read as a prefix inside the bucket
  named in the location, consistent with virtual-hosted-style addressing. A
  `root` that starts with the bucket name keeps its previous meaning as
  `/<bucket>/<prefix>`.

## Fixes

- Source and destination connectors now apply `root` with virtual-hosted-style
  addressing. A prefix given both in the location path and in `root` must match.
