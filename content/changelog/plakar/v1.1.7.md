## Security

- Signing in from the Plakar UI now presents the confirmation code introduced in
  v1.1.6 for `plakar login`, so both sign-in paths use the same hardened flow.

## New

- The `fs` exporter accepts new `skip_ownership`, `skip_permissions`,
  `skip_times` and `skip_root_perms_and_time` options.
- The UI shows `sync` progress.
- Deleting several snapshots at once takes a single state write.

## Fixes

- Malformed sign-in requests to the API (bad body, invalid email, invalid poll
  ID) return 400 instead of 500. An expired sign-in returns 404.
- `plakar login` handles HTTP 429 (too many requests) from the backend
  correctly.
- `backup` lock handling is more robust:
  - Lock refresh errors are no longer dropped silently. Plakar retries, then
    aborts the backup, so a lock can no longer go stale unnoticed.
  - Unlocking waits for the lock to be deleted, so slow storage is not left with
    a stale lock.
  - A transient lock read failure no longer aborts the backup early.
  - Stale lock detection skips the backup's own lock.
- A race that could crash Plakar at the end of a `restore` is fixed.
- On Windows, the `/` entry of snapshots made with the `fs` integration is
  fixed. Snapshots already affected can be browsed and maintained again.
- On Windows, the `fs` importer applies exclusions correctly and names the `C:\`
  entry correctly.
- Package installation on Windows is fixed.
