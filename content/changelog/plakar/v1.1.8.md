## Security

- Plakar is rebuilt with Go 1.26.10, which fixes CVE-2026-111943
  ([golang/go#82345](https://github.com/golang/go/issues/82345)). `crypto/x509`
  now refuses certificate chains that go through a small set of intermediate
  certificates from one Certificate Authority. Binaries built with an earlier Go
  still trust those intermediates.
- The fix applies wherever Plakar verifies TLS certificates: object storage such
  as S3 and compatible services, HTTP stores, the plakar.io authentication
  service, and every integration that uses TLS. A server presenting a chain
  through one of the blocked intermediates is now rejected.
- Kloset data is not exposed by this issue. Everything written to a repository
  is encrypted and authenticated locally with a key derived from the passphrase,
  and neither the passphrase nor the key goes over the network. Plugins from
  plakar.io are signed and verified independently of TLS.
- An intercepted connection could still affect repositories opened with
  `PLAKAR_INSECURE_PLAINTEXT`, which have no encryption of their own, the
  availability of the connection, and credentials sent over TLS such as the
  plakar.io login session.
- If a remote that used to work fails certificate verification after upgrading,
  its chain goes through a blocked intermediate. Contact the service provider
  rather than disabling TLS verification.

## Breaking changes

- Building from source requires Go 1.26.10 or later. An older toolchain refuses
  to build, or fetches 1.26.10 itself when `GOTOOLCHAIN=auto` is set. The
  Dockerfile builder stage now uses `golang:1.26-alpine`.
